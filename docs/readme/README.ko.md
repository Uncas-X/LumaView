**[macOS 앱 다운로드](https://github.com/Uncas-X/LumaView/releases/latest/download/LumaView-macOS.zip)** · [버전 및 업데이트 안내](https://github.com/Uncas-X/LumaView/releases)

macOS 13+를 지원하며 하나의 패키지로 Intel과 Apple Silicon에서 실행됩니다. ZIP을 내려받아 압축을 풀고 `LumaView.app`을 “응용 프로그램”으로 드래그하면 설치됩니다.

Picasa Photo Viewer의 빠른 보기 방식을 참고한 macOS 네이티브 미디어 뷰어입니다. 같은 폴더 탐색, 확대·축소, 드래그, 회전, 필름스트립, 전체 화면과 슬라이드쇼를 지원합니다. 1.5에서는 오디오 표지와 실제 샘플 기반 파형, 다중 페이지 문서 탐색, 확대율에 맞춰 그리는 벡터 캔버스, 기본적으로 시스템을 따르는 다국어 설정을 추가했습니다. 독립적인 이름과 자체 아이콘을 사용하며 과거 Picasa의 모든 기능과 조작이 완전히 같다고 주장하지 않습니다.

1.7.2는 이미지 투명 영역 표시를 통일했습니다. PNG, GIF, PSD / PSB 같은 래스터 이미지의 투명 부분에는 현재 보기 배경이 보이며 그림자는 실제 윤곽과 투명도를 따릅니다. 체크무늬나 투명 캔버스 전체의 사각형 그림자를 표시하지 않습니다. PDF 등의 문서는 계속 흰 종이로 표시합니다.

1.7.1의 PSD / PSB 미리 보기 개선도 유지합니다. 필름스트립은 유효한 내장 JPEG를 우선 읽고 주 화면은 실제 호환 합성 이미지를 디코딩합니다. RLE를 블록 단위로 읽으며 일부 ICC 프로파일이 있는 작은 합성 이미지에서 썸네일 생성이 실패하던 문제도 수정했습니다.

## 사용 및 설치

macOS 13 이상이 필요하며 Intel과 Apple Silicon을 지원합니다.

1. [Releases](https://github.com/Uncas-X/LumaView/releases)에서 `LumaView-macOS.zip`을 내려받아 풀고 `LumaView.app`을 “응용 프로그램” 폴더로 옮겨 실행합니다.
2. 이미지, 비디오, 오디오 또는 폴더를 드래그하거나 `⌘O`로 파일을 선택합니다. 하나의 파일을 열면 같은 폴더의 미디어를 나열하고, 여러 파일을 선택하면 선택한 파일을 탐색합니다. 폴더는 바로 아래 항목만 검색하며 하위 폴더를 재귀 검색하지 않습니다.
3. Finder에서 파일을 오른쪽 클릭하여 “다음으로 열기 → LumaView”를 선택할 수도 있습니다.

로컬 빌드는 임시 서명이며 Apple 공증을 받지 않았습니다. 다른 Mac에서 내려받은 사본을 Gatekeeper가 차단하면 출처를 확인한 뒤 시스템 “개인정보 보호 및 보안”의 열기 허용 기능을 사용할 수 있습니다.

## 기본 앱 설정

**LumaView → 기본 앱…**, `⌘,` 또는 “더 보기” 메뉴에서 설정을 엽니다. 형식은 이미지, 벡터 / 문서, 비디오, 오디오로 묶이며 검색 후 선택하여 “선택한 형식의 기본 앱으로 설정”을 누릅니다. 대화상자를 열 때, 앱이 다시 활성화될 때, 설정이 끝났을 때 실제 시스템 연결을 읽습니다. 체크는 그룹의 모든 유형이 현재 LumaView에 연결되었음을, 가로선은 일부만 연결되었거나 다른 사본을 가리킴을 뜻합니다. 연결은 재시작 후에도 유지하며 미적용 선택을 성공으로 표시하지 않습니다. 상단 “모든 형식 선택”은 검색과 무관하게 모든 이미지, 벡터 문서, 비디오, 오디오를 선택하고 각 분류도 따로 전체 선택할 수 있습니다. 비우기는 이번 선택만 지우며 기존 시스템 연결은 해제하지 않습니다.

설정 진행률을 표시하고 결과를 항목별로 다시 읽습니다. 취소하면 이후 설정을 멈추되 완료한 변경은 유지합니다. 형식 목록은 선택할 수 있는 파일 연결이며 내부 인코딩과 모든 파일을 실측한 호환 목록이 아닙니다. 범위는 [형식 및 미리 보기 안내](../i18n/ko/FORMATS.md)를 참고하세요.

## 보기 및 재생

첫 파일을 열면 현재 화면의 사용 가능한 영역으로 펼쳐지며 `F`로 전체 화면에 들어갑니다. 아래 필름스트립에서 파일을 바로 바꿀 수 있습니다. 포인터가 화면 영역에 잠시 머무르면 조작 막대가 숨겨지고 움직이면 다시 나타납니다.

1.5.2에서는 큰 폴더를 연속 탐색할 때 썸네일이 비거나 깜박이는 문제를 수정했습니다. 보이는 썸네일은 별도로 유지하고 화면 밖 로드는 즉시 취소합니다. 폴더를 바꾸면 오래된 결과가 새 목록에 기록되지 않습니다. 디코딩 불가 파일은 안정된 대체 그림을 보여주며 해당 범위에 다시 들어오면 재시도할 수 있습니다.

이미지와 비디오 모두 확대·축소, 드래그, 회전, 전체 화면을 지원합니다. 창, 이미지 변경, 확대·축소와 회전에는 짧고 부드러운 전환을 적용하며 연속 조작으로 중단할 수 있습니다. 시스템 “동작 줄이기”를 켜면 자체 전환은 꺼지지만 움직이는 이미지는 정상 재생됩니다. 기본은 반투명 유리 배경이며 스페이스로 유리, 어두운 배경, 밝은 배경을 전환합니다.

래스터 투명 영역은 현재 배경을 보여주는 동일 규칙을 사용합니다. 그림자는 내용이 있는 픽셀만 따르고 반투명 가장자리의 투명도를 유지합니다. GIF / APNG 재생 시 프레임에 따라 그림자도 변합니다. 이미지 복사는 원래 투명 픽셀을 유지하며 뷰어 배경이나 그림자를 포함하지 않습니다.

오디오·비디오의 재생, 정지, 진행률, 음량 컨트롤은 필름스트립 위에 있습니다. 열면 자동 재생하고 끝에서는 멈추며 `P`로 다시 재생할 수 있습니다. `S`는 정지 후 처음으로 돌아갑니다. 아래 슬라이드쇼 버튼과 미디어 재생 버튼은 별개입니다. `⌘4`로 연속 재생하면 이미지는 지정 간격으로 바뀌고 오디오·비디오는 재생 종료 후 바뀝니다. 미디어만 재생할 때는 다음 항목으로 자동 이동하지 않습니다.

macOS 기본 재생을 우선 사용합니다. 직접 재생할 수 없으면 내장 유니버설 FFmpeg 9.0.2와 dav1d 1.5.3으로 로컬 호환 파일을 만듭니다. 가능하면 먼저 컨테이너 변경을 시도하고 그다음 트랜스코딩합니다. 별도 플레이어, Homebrew, 코덱 팩은 필요 없고 네트워크에 접근하지 않습니다. 호환 재생은 전체 파일 준비를 기다리며 그동안 진행률을 표시합니다. 파일 변경이나 창 닫기로 취소합니다. 긴 비디오는 첫 준비에 시간과 추가 디스크 공간이 많이 필요할 수 있습니다.

`C` 또는 “더 보기”에서 순환 탐색, 휠 동작, 배경 클릭 닫기, 필름스트립, 정렬, 슬라이드쇼 간격(2, 3, 5, 8, 10초)을 설정합니다. 휠 기본 동작은 확대·축소이며 `Ctrl`을 누르면 잠시 파일 탐색으로 바뀝니다. 기본을 탐색으로 설정했다면 `Ctrl`로 잠시 확대·축소합니다. “이미지 밖 배경 클릭 시 닫기”는 기본 활성화됩니다. 설정은 로컬에 저장합니다.

## 오른쪽 클릭 메뉴와 복사

주 화면에서 오른쪽 클릭(또는 Ctrl 클릭)하면 “다음으로 열기 → 앱 / 다른 앱…”과 “Finder에서 보기”를 선택할 수 있습니다. 다음으로 열기는 이번 열기에만 적용하고 기본 연결은 바꾸지 않습니다. 디코딩할 수 없는 파일에도 이 두 기능을 사용할 수 있습니다.

- 이미지: “이미지 복사”를 선택합니다. 현재 화면의 회전과 투명 픽셀을 유지하고 현재 디코딩된 이미지 전체를 복사합니다. 도구 막대나 확대된 화면 영역을 캡처하지 않습니다.
- 비디오: “현재 프레임 복사”를 선택합니다. 메뉴를 연 시점의 비디오 프레임을 복사하며 비디오 방향과 보기 회전을 유지합니다. 재생 위치와 상태는 변경하지 않습니다.
- PDF / PDF 호환 AI: 페이지의 비트맵을 오른쪽 클릭하여 “이 이미지 복사” 또는 “현재 페이지 복사”를 선택합니다. 확대, 이동, 회전 후에도 실제 클릭 위치로 판별합니다. 일반 텍스트와 벡터 영역은 이미지로 취급하지 않습니다. 복잡한 마스크나 색 공간은 해당 이미지 영역의 보이는 결과를 복사하므로 겹친 텍스트를 포함할 수 있습니다. 한 장의 이미지로 스캔한 페이지는 전체 스캔을 복사합니다.
- `⌘C`는 현재 이미지, 비디오 프레임, 문서 페이지를 복사합니다. 오디오는 이미지 복사를 제공하지 않습니다. 클립보드에는 PNG와 TIFF를 제공하며 파일 / 페이지 변경 또는 닫기 후 오래된 복사 결과가 덮어쓰지 않습니다.

문서와 내장 이미지 복사는 긴 변 최대 8192픽셀, 약 3200만 픽셀의 비트맵을 생성하며 PDF/SVG 벡터 명령을 클립보드에 쓰지 않습니다. 대형 이미지가 제한된 미리 보기로 표시 중이면 그 미리 보기를 복사합니다. PDF 이미지 탐색에는 복잡도 한계가 있습니다. 패턴 채우기 안의 이미지 등은 개별 선택이 불가능할 수 있지만 현재 페이지는 복사할 수 있습니다.

표준 SVG 1.0/1.1 헤더는 오프라인으로 해석하며 외부 DTD를 읽지 않습니다. 1.7은 Ghostscript 10.08.0을 내장하여 EPS / PostScript와 구형 PostScript AI를 경로, 텍스트, 내장 이미지를 유지하는 PDF로 변환합니다. 주 화면은 확대율에 맞춰 벡터를 다시 그리며 다중 페이지 PS는 기존 페이지 탐색을 사용합니다. 별도 소프트웨어는 필요 없습니다. 변환이 실패해도 유효한 내장 TIFF가 있는 EPS는 미리 보기로 대체하고 TIFF라고 표시합니다. 원래 비트맵이 벡터가 되지는 않습니다.

## 오디오, 문서와 언어

오디오에 내장 표지가 있으면 주 화면에 우선 표시합니다. 유효한 표지가 없으면 실제 샘플을 비동기 분석하여 전체 오디오 파형을 표시합니다. 분석 중에는 대체 그림을 표시하며 파형 완료를 기다리지 않고 재생합니다. 오디오와 비디오는 필름스트립 오른쪽 아래에 같은 글꼴, 배경, 위치로 `▶ 재생 시간`을 표시하고 아직 읽지 못했으면 `▶ –:––`를 표시합니다. 표지는 파일 내장 메타데이터에서만 읽고 네트워크나 같은 폴더의 이미지는 검색하지 않습니다.

PDF, PDF 호환 AI, 다중 페이지 TIFF는 내부 페이지 탐색을 지원합니다. 작은 페이지 썸네일, 페이지 진행 막대, 현재 / 전체 페이지 수가 파일 필름스트립 위에 표시됩니다. `↑`는 페이지, `↓`는 파일에 초점을 둡니다. 현재 층의 선택 썸네일은 주황 테두리로 초점을, 다른 층은 회색 테두리로 선택 상태를 나타냅니다. 별도의 “페이지 / 파일” 라벨은 없습니다. `←` / `→`, `J` / `K`, `Home` / `End`는 현재 초점을 조작하며 층을 클릭해도 초점이 이동합니다. 페이지 처음과 끝에서 멈추므로 다른 파일로 넘어가지 않습니다. 아래 이전 / 다음 파일 버튼은 항상 파일을 바꿉니다. 파일 필름스트립을 숨겨도 페이지 탐색은 유지됩니다.

PDF, SVG, PDF 호환 AI는 고정 미리 보기를 늘리는 대신 원본 벡터 명령으로 현재 확대율의 보이는 영역을 그립니다. 문서 투명 영역은 체크무늬 없는 흰 종이로 표시합니다. 페이지 변경 시 새 페이지 전체가 준비된 뒤 전체 페이드 전환을 하므로 백그라운드 벡터 세부 묘사 때문에 빈 타일이 차례로 나타나지 않습니다. 내장 사진 같은 비트맵은 원본 해상도에 제한됩니다.

**LumaView → 언어…** 또는 “더 보기”에서 언어를 선택합니다. 기본은 시스템을 따르며 중국어 간체, 번체, 영어, 일본어, 한국어, 프랑스어, 독일어, 스페인어, 이탈리아어, 포르투갈어, 러시아어, 아랍어, 힌디어, 튀르키예어, 네덜란드어, 폴란드어를 지원합니다. 앱 메뉴, 도구 설명, 페이지 탐색, 설정 화면이 즉시 갱신되고 선택은 로컬 저장됩니다. 지원하지 않는 시스템 언어는 영어로 대체하며 드문 디코딩 오류도 영어일 수 있습니다. 파일명, 경로, 파일 속 원래 텍스트는 그대로입니다.

## 지원 범위와 제한

- 이미지는 시스템 ImageIO로 디코딩합니다. JPEG, PNG, GIF, HEIC, TIFF, BMP, WebP, RAW 등의 실제 지원은 시스템 버전과 파일 내용에 달려 있습니다.
- 대형 이미지는 1.5억 픽셀 초과만으로 거부하지 않습니다. 메모리를 제한하기 위해 필요 시 축소 미리 보기를 생성하며 원본 크기와 방향은 보존합니다. 100% 배율도 원본 크기로 계산하지만 미리 보기에서 디코딩하지 않은 세부 픽셀은 복원하지 못합니다.
- SVG, PDF, PDF 호환 AI 및 내장 해석기가 처리하는 EPS / PS / 구형 AI의 벡터 표시를 지원합니다. 다중 페이지 PDF / AI / PS는 페이지 이동이 됩니다. SVG는 스크립트와 외부 리소스를 거부합니다. 내부 비트맵은 원본 해상도에 제한되며 포함되지 않은 사용 불가 글꼴은 대체될 수 있습니다.
- PostScript는 독립 프로세스에서 SAFER와 시스템 샌드박스를 사용합니다. 현재 임시 입력·출력만 허용하고 네트워크는 금지합니다. 빠른 파일 전환으로 취소할 수 있으며 썸네일과 주 화면은 완료된 캐시를 공유합니다. 해석 1회 제한은 90초, 출력은 최대 1 GB, 캐시 정리 목표는 2 GB입니다.
- Photoshop PSD / PSB는 저장 시의 합성 이미지를 표시하며 레이어 편집은 없습니다. 대형 캔버스는 메모리 예산으로 미리 보기를 만들고 원본 크기를 유지합니다. 색 모드, 비트 깊이, 압축 지원은 FORMATS.md를 참고하세요.
- 내장 호환 디코딩이 오디오·비디오 범위를 넓히지만 DRM, 손상 파일, 사용할 디코더가 없는 독점 인코딩은 재생 불가일 수 있습니다. 확장자만으로 내부 인코딩을 보장하지 않으며 모든 형식, 장치, 시스템 버전을 개별 실측하지 않았습니다.
- 호환 캐시 정리 목표는 2 GB이나 사용 중인 파일 때문에 잠시 넘을 수 있습니다. 준비 파일 하나는 최대 8 GB이며 디스크 여유를 최소 512 MB 남깁니다. 공간이 부족하면 준비를 중단하고 알립니다.
- TIFF는 다중 페이지를 지원하며 페이지 기능이 없는 다른 복합 이미지는 첫 장만 표시합니다. 보기 회전은 원본에 기록하지 않습니다. 편집, 삭제, 사진 라이브러리 데이터베이스, 공유, 클라우드 동기화, 외부 자막 관리 기능은 없습니다.
- 사용자가 연 로컬 미디어와 해당 폴더만 읽습니다. 호환 재생은 로컬 캐시에 기록하며 미디어를 업로드하거나 원본을 수정하지 않습니다.

추가 형식 예제, 캐시와 미리 보기의 한계는 [FORMATS.md](../i18n/ko/FORMATS.md)를 참고하세요.

## 소스에서 빌드

Xcode 또는 Swift 컴파일러를 포함한 Command Line Tools가 필요합니다. 저장소와 소스 패키지에는 Intel / Apple Silicon 유니버설 미디어 도구가 포함되어 일반 빌드 시 외부 의존성을 별도 설치하거나 내려받을 필요가 없습니다. 복제 또는 다운로드 후 `build.sh`가 있는 저장소 루트에서 빌드하면 되며 원래 개발 작업 공간 구조는 필요 없습니다.

```bash
cd /path/to/LumaView
./build.sh
open ../LumaView.app
```

기본은 유니버설 앱이며 `./build.sh --host`는 현재 Mac 아키텍처만 빌드합니다. 앱 기본 위치는 소스 폴더 옆의 `LumaView.app`이며 `LUMAVIEW_APP_PATH`로 바꿉니다. 빌드·테스트 작업 폴더는 기본적으로 저장소의 `.build/`이고 `LUMAVIEW_WORK_ROOT`로 변경합니다. 생성 파일은 `.gitignore`로 제외합니다.

테스트 빌드는 `LUMAVIEW_TEST_BUILD=1 ./build.sh --host`를 사용해 독립된 `LumaView Tests` 앱을 만듭니다. 파일 연결을 선언하지 않아 정식 설치본의 연결을 차지하지 않습니다. UI 테스트 스크립트의 기본 모드이며 `LUMAVIEW_SKIP_TEST_BUILD=1`과 `LUMAVIEW_TEST_APP_PATH`로 기존 빌드를 지정할 수 있습니다.

FFmpeg는 LGPL 2.1 이상으로 빌드하고 정적 링크된 dav1d는 BSD 2-Clause 라이선스입니다. 대응 소스 압축 파일, 체크섬, 라이선스가 소스 패키지에 포함됩니다. 미디어 도구 재빌드에는 Xcode Command Line Tools, Python 3, Meson 1.12.1, Ninja 1.13.2가 필요합니다. Python 가상 환경에 설치한 후 `./tools/build-media-tools.sh`를 실행합니다. 상세 단계와 구성은 [ThirdParty/README.md](../i18n/ko/ThirdParty/README.md)를 참고하세요. PostScript에는 독립된 Ghostscript 10.08.0(AGPL-3.0-or-later)을 사용하며 라이선스, 전체 대응 소스, 빌드 스크립트를 포함합니다. 일반 앱 빌드는 동봉된 이중 아키텍처 구성 요소를 사용하며 재빌드는 [Ghostscript 안내](../i18n/ko/ThirdParty/README-Ghostscript.md)를 참고하세요.

## 소스와 검증

- `Sources/`: AppKit UI, 미디어 캔버스, 이미지·벡터 로딩, 오디오·비디오 수명 주기, 호환 준비, 기본 앱 설정.

오디오 디코딩 단위 테스트는 MP3 / FLAC / Opus 샘플 생성에 해당 인코더가 있는 개발용 FFmpeg가 필요하며 `LUMAVIEW_TEST_FFMPEG`로 경로를 지정합니다. 앱 실행과 오디오 UI 테스트는 포함된 구성 요소만 사용합니다.

UI 통합 검사는 로그인된 macOS 그래픽 데스크톱이 필요하며 앱을 열고 자동 생성 미디어로 조작을 검사합니다. 빌드 파일과 저장 보고서는 기본적으로 `.build/`, 일부 실행 자료는 시스템 임시 폴더를 사용합니다. 기본 테스트는 개인 사진을 읽지 않습니다. 오른쪽 클릭 복사 테스트는 별도의 이름 있는 클립보드로 현재 복사 내용을 보존하며, 다음으로 열기 / Finder / 기본 앱 테스트는 모의 인터페이스로 파일 연결을 변경하지 않습니다. 배포 버전 검증은 [TEST-RESULTS.txt](../i18n/ko/TEST-RESULTS.md)에 있습니다.

`Tests/`의 저장 보고서는 해당 버전의 과거 검증 기록이며 복제 후 현재 환경이 자동으로 통과했다는 뜻이 아닙니다. 개인 샘플 파일명은 익명화했고 원본 미디어는 저장소에 넣지 않았습니다. 과거 보고서의 `work/` 경로는 당시 테스트 출처이며 현재 빌드 필수 폴더가 아닙니다. 외부 도구의 대응 소스 압축 파일, 체크섬, 라이선스를 보존하므로 최초 복제 용량이 큽니다.
