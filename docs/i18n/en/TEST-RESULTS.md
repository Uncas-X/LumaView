Version 1.7.2, build 14. Tested on 2026-10-22 with macOS 15.7.9 / Intel. The app and bundled tools were checked as universal arm64 + x86_64 binaries with local signatures. This round did not run on Apple Silicon hardware.

## Fix in this release

Raster images now show transparent regions consistently: PNG / GIF / PSD / PSB and others no longer draw a gray-white checkerboard or a rectangular canvas border. Display shadows derive from the actual composited alpha of the current picture instead of the whole image canvas. Transparent margins therefore have no extra rectangular shadow; holes, separate soft masks, and translucent regions contribute to the actual outline.

The old implementation only looked at CGImage.alphaInfo when adding the checkerboard, missing PSB files with a separate Quartz mask. It also forced a rectangular shadowPath on every zoom, and the border itself produced a rectangular shadow. Those rectangular sources have been removed for raster images; layer shadows now follow composited alpha automatically. Export drawing likewise casts a shadow from the image itself without filling a rectangle first. GIF / APNG frame changes replace the current texture and update the shadow without scanning every frame's transparent pixels or building a full extra RGBA image.

Document pages keep their white paper, and video surfaces retain their existing rectangle. Image copying still uses original image pixels without the viewer background, checkerboard, or display shadow. The PSB decoder, thumbnail scheduler, and previous release's fast-preview path were not changed.

Transparency tests used one graphic with a hole, irregular protrusions, and large transparent margins, encoded separately as RGBA, a separate Quartz mask, and actual PNG, GIF, PSD, and PSB files that were encoded and decoded. CALayer compositing and exported pixels from `draw` were checked to confirm no rectangular backing/shadow on transparent edges and shadows on internal and external contours. Fully transparent images, frame changes, rotation and zoom, rapid switching, and a translucent viewer background were also covered. Exported PNGs were visually inspected.

For these six inputs, the PNG SHA-256 of the CALayer export and the PNG `draw` export were identical: `578021195e2a41b30187ebc271542d599aecba7f0b9204fbfdf21eb680cac18c`. Test media was generated by code; no personal photos were added to the source.

A bounded software-rendering probe also compared the new and old shadows at fit-to-window, 100%, and 3200% on a 32 MP bitmap with logical canvases of 16,384 × 7,812 and 300,000 × 128. Peak test-process RSS was about 428 MiB; old and new rendering times were similar. That measures software snapshots via `CALayer.render(in:)`, not GPU frame rates. No layer raster cache was added as a result.

Complete file lists and hashes of the installed release app and `outputs/LumaView.app` matched; both passed `codesign --verify --deep --strict`. The previous ZIP was backed up before installation. Default-opening associations were read back before and after. CRC and version checks of the delivered ZIP followed. Historical reports remain in `Tests/Release-1.7.0.md` and `Tests/Release-1.7.1.md`; checks not rerun from those releases do not enter this round's count.

Main executable SHA-256: `b022867c703cb1cdc94c31589d040356a5ec2be9bc5dd0c17395d323f8556d4e`.
